# U1 L15 — Unit 1 Review Session 2 & Exam Strategy (TECH DAY)

**LO:** consolidate Unit 1 before tomorrow's assessment, and learn how to attack a paper exam you have only seen once.

Tomorrow is the Unit 1 assessment. Today is the last session before it. You are
not learning new material today — you are making sure nothing is a surprise
tomorrow.

## PART 1 — THE RED LIST, ROUND TWO (20 min)

Take the honest traffic-light list you made yesterday. For every **Red** and
**Yellow**:

- Write a one-line definition of it, in your own words, in your notes.
- Solve one tiny example by hand.
- If it is still Red after that, **write it down and bring it tomorrow**. Do
  not spend the whole period on one topic you have not clicked yet. There is
  more value in covering three topics shallowly than one topic deeply — the
  assessment asks about all of them.

A Yellow that becomes Green today is a topic you just walked into free points
on tomorrow.

## PART 2 — HOW TO ATTACK A PAPER EXAM (20 min)

Tomorrow is closed-computer: pen, paper, 35 minutes, no notes. That format
changes how you should prepare. Work through this with the group.

**Timing.** Ten short-response questions at 2 points, then longer problems. If
you are spending more than about 90 seconds on a short-response item, move on
and come back. Getting 9 of 10 easy ones right beats 6 hard ones and four
unanswered.

**Reading the verb.** The question tells you the answer's shape:

| Verb | Means | Example answer |
|---|---|---|
| What is / What type | A value or type | `3.5`, type `float` |
| Why / Explain | A sentence, or two | "Because `input()` returns a string" |
| Write code | Actual code, complete | A full `try/except` block |
| What happens when… | Trace it, do not fix it | The actual error type and message |

Students lose points here by answering "what happens" with a *fix*. The
question asks what happens. Answer that.

**Show your work on the code questions.** A `try/except` that asks again
scores higher than one that exits — but only if you write both clearly. Partial
credit is real.

## PART 3 — STRESS TEST (20 min)

Closed notes, 20 minutes, on paper. This is the closest thing to tomorrow, and
it is meant to be uncomfortable:

1. Ten short-response questions covering types, conversion, `try/except`,
   division by zero, and the `10**15` bound.
2. One code question: write a function that takes user input and returns a
   valid integer, or explains why it cannot.
3. One conversion question with a boundary: −273.15 °C, and 0 K.

**Then mark your own work honestly.** Red-pen it. Count how many you would have
lost points on through carelessness alone — forgetting a `try`, writing
`input() + 1`, forgetting to answer *why*.

If you lost points to carelessness, that is the most useful finding of the
week. It is also the easiest to fix: slow down by ten seconds per question.
