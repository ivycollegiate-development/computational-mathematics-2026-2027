## THE PRACTICE EXAM (35 min, closed notes)

Work alone and in silence. Move on if you stall; come back if time allows.

### Section A — Short Response (10 questions)

Answer in a full sentence where it asks *why*; a value or type is enough where
it asks *what*.

1. What does `7 / 2` return, and what is its type? What about `7 // 2`?
2. What does `7 % 2` return, and what does that operation actually mean?
3. Why must you wrap `input()` in `int()` or `float()`? What is the type of
   `input()` on its own?
4. Write the `try/except` block that catches non-numeric input and asks the
   user again.
5. What exception does `10 / 0` raise, and why?
6. `2 ** 100` — does this overflow in Python? What is the security concern
   with unbounded exponentiation?
7. Why did we set a `10**15` ceiling on conversions? Name one real system where
   a silent overflow caused harm.
8. Convert −40 °C to Kelvin. Is the result physically meaningful?
9. What is the difference between a program that **crashes** and one that
   returns a **quietly wrong answer**? Which is more dangerous, and why?
10. In one sentence: what is *defensive programming*?

### Section B — Code (2 questions, 5 points each)

11. Write a function that takes a user's input and returns a positive integer,
    re-asking until it gets one. Handle both non-numeric input and zero or
    negative values.

12. Write a function `c_to_k(c)` that converts Celsius to Kelvin and refuses
    any value below −273.15, returning a clear message rather than a number.

**Mark your own work when I say time.** Red pen. Be strict — a `try` that is
missing its `except` is a wrong answer, not a nearly-right one. The goal is to
find your gaps one day before it costs you.
